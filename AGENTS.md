# JanSetu

## Project

JanSetu is a citizen-facing Indian government-service navigation and rejection-resolution platform.

## Tech Stack

- Next.js 14
- React 18
- TypeScript
- Tailwind CSS
- App Router
- npm

## Development Commands

- npm run dev
- npm run build
- npm run lint

## General Rules

- Inspect existing code before modifying it.
- Do not unnecessarily rewrite working code.
- Keep components reusable and maintainable.
- Keep the UI responsive and accessible.
- Do not hardcode secrets, credentials, API keys, or tokens.
- Do not create unnecessary dependencies.
- Do not modify unrelated files.
- Run appropriate validation after significant changes.
- Preserve existing functionality when adding features.
- Keep the project structure organized.
- Prefer clear, readable TypeScript.
- Use proper error handling.
- Avoid duplicated logic.
- Keep sensitive user data out of logs.
- Do not claim that mock functionality is a real government integration.

## Git Rules

- Work in small, logical changes.
- Do not reset, delete, or rewrite Git history unless explicitly instructed.
- Do not force-push.
- Do not modify the main branch history.
- Create meaningful commits after major completed milestones.
- Before major changes, inspect the current Git status.

## Collaboration Rules

- Assume another developer may continue the project later.
- Leave the project in a runnable state.
- Document important architectural decisions.
- Do not remove functionality simply because it is unfamiliar.
- When continuing existing work, inspect what has already been implemented before starting.
- Never recreate an existing feature from scratch without first checking the current implementation.

## Before Completing a Task

- Check the files you changed.
- Run relevant validation.
- Confirm the application still builds.
